## Overview

Block Party is the rendered documentation site for Playcraft's AutoCAD-focused playground-design tools. It provides a convenient reference for design resources, implementation information, and project documentation without requiring readers to follow the underlying source workflow.

The repository uses CI to publish generated documentation in a viewable form. As a result, teams working with the Playcraft ecosystem have a consistent presentation of the latest material and a straightforward way to inspect the generated pages.

## Getting Started

Download or clone the repository, then view its generated documentation or build output in a browser or compatible documentation viewer.

1. Clone the repository:
   `git clone https://github.com/chris-colepi1555/block-party-autocad-tools.git
2. Move into the project directory:
   `cd block-party`
3. Open the generated documentation entry point, or visit the published site:
   `https://chris-colepi1555.github.io/block-party-autocad-tools/

For local use, locate the output directory produced by the CI build and open the rendered HTML files directly.

## Working With the Documentation

Use the published Block Party site to consult Playcraft's AutoCAD playground-design reference material.

A typical review process is:

1. Load the current published build.
2. Select the rendered topic or page you need.
3. Examine the included diagrams, notes, and text.
4. Revisit the newest CI-published build whenever documentation changes are released.

After cloning the project, local review is also possible by opening the generated HTML pages in a web browser.

## Build and Content Configuration

Block Party is focused on generated documentation. Configuration is therefore maintained in the project source and CI workflow rather than through a user-facing preferences interface.

If you are responsible for maintaining the build:

- ensure generated files match the CI publication step
- change the source documentation before generating a new build
- do not manually modify rendered pages when those files are controlled by the pipeline

## Frequently Asked Questions

**Where can I find the newest version?**  
Open the published site or use the latest build link above. This repository is designed to expose the output generated by CI.

**Is it okay to change rendered pages manually?**  
No. Update the source documentation and rebuild it through the pipeline instead of editing generated files directly.

**Where does the project keep its settings?**  
Content and build configuration belong in the source project and CI configuration. There is no separate application preferences screen.

**What can I check if the documentation does not open?**  
Verify that publication completed successfully, check the site URL, and reload the page after the latest CI run has finished.
